# 完整测试记账 APP

针对「记账 APP」这个项目，运行全部测试并给出**明细报告**，按下面步骤：

## 第一步：跑测试，拿逐条结果

1. 运行 `npm run test:report`（等于 `vitest run --config vitest.config.ts --reporter=verbose`），它会**逐条列出每个测试用例的名字和 ✅/❌ 结果**。
   - 一定要用 `npm test` / `npm run test:report`，**不要直接 `npx vitest run`**，否则会踩到下面「配置文件冲突」的坑。
2. 把输出里每一行 `✓ / ✗ 文件名 > 描述 > 用例名` 记下来，作为明细的依据。

## 第二步：生成明细报告（汇总 + 明细）

报告必须包含**汇总**和**明细**两部分。明细按「类型」分三组，每组列出：测试文件、测的功能、用例数，以及**每一个用例的名字和 ✅/❌ 状态**。格式如下：

```
## 测试汇总
- 测试文件：9 个（全部通过 ✅）
- 测试用例：35 个（全部通过 ✅）
- 失败：0 个
- 耗时：约 X 秒

## 测试明细（按类型）

### 一、工具函数（纯计算）
- 文件：src/utils.test.ts（测 src/utils.ts）｜功能：金额换算、日期处理｜共 7 个
  - ✅ 元转分
  - ✅ 分转元（数字）
  - …（每个用例一行，标 ✅/❌）

### 二、数据库计算逻辑
- 文件：src/db-logic.test.ts（测 src/db-logic.ts）｜功能：收支汇总、筛选、月份补齐｜共 12 个
  - …（每个用例一行）

### 三、页面组件
- 文件：src/views/*.test.ts + src/App.test.ts｜功能：各页面行为｜共 16 个
  - …（每个用例一行）
```

归类规则（固定，别搞错）：
- `src/utils.test.ts` → 工具函数
- `src/db-logic.test.ts` → 数据库计算逻辑
- `src/App.test.ts` + `src/views/*.test.ts` → 页面组件

## 第三步：下结论

- 全部通过 → 告诉用户「所有测试通过，APP 各环节正常」。
- 有失败 → 判断是「代码有 bug」还是「测试写错了」，用大白话说明原因并给修复建议；修好后重跑直到通过。

## 铁律：如实汇报，绝不编造

- **必须真的运行测试命令，用命令的真实输出**生成报告，禁止凭记忆或 README 里的「35 个用例」编数字。
- 如果命令报错，就把真实报错告诉用户，不要假装「全部通过」。

## 这套测试覆盖了什么（大白话）

- **工具函数**（`src/utils.ts`）：金额换算、日期加减这些纯计算。
- **数据库计算逻辑**（`src/db-logic.ts`）：收支汇总、筛选条件拼接、月份补齐这些规则。
- **页面组件**（`src/views/*.vue` + `src/App.vue`）：记账校验、账单金额显示、删除确认、分类新增、菜单切换等行为。

## 写测试时要注意的坑（遇到报错先看这里）

- **配置文件冲突（最重要）**：项目里同时有 `vite.config.ts`（异步配置）和 `vitest.config.ts`（同步配置），vitest 4 默认会读到异步的 `vite.config.ts` 然后报 `Cannot read properties of undefined (reading 'config')`。**解决**：跑测试务必带 `--config vitest.config.ts`（项目里的 `npm test` / `npm run test:report` 脚本已经加好了，直接用即可）。
- **页面组件要用「假浏览器」**：每个组件测试文件顶部必须有 `// @vitest-environment jsdom` 这行，否则会报 `document is not defined`。
- **数据库要用「假数据」**：组件测试里用 `vi.mock('../db', ...)` 替换真实的数据库模块，避免测试时真的去读写 SQLite。
- **图表（ECharts）和贪吃蛇画面测不了**：用假对象替代，只测行为逻辑（比如「拉没拉数据」「点开始按钮状态对不对」），不测画面。
- **jsdom 缺浏览器 API**：`test-setup.ts` 里已经补齐了 ResizeObserver、matchMedia，别删它。
